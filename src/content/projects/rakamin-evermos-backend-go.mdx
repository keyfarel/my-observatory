## Overview

A backend service built with Go (Golang) implementing Clean Architecture. Developed as a final project for the Rakamin Academy × Evermos Virtual Internship, this API handles the complete e-commerce lifecycle: from authentication and multipart product uploads to atomic transactions and logistics mapping.

Post-internship, I re-opened the project for a major refactor, focusing heavily on system architecture, transaction security, and reliability under load.

## Architecture

The project strictly follows Clean Architecture to decouple business logic from external frameworks and infrastructure.

## Core Engineering

The refactoring process introduced several critical mechanisms:

- **Row Locking (Pessimistic Lock):** Utilized `SELECT ... FOR UPDATE` during the checkout flow to strictly prevent overselling and race conditions when multiple users attempt to purchase the same inventory simultaneously.
- **Idempotency & Snapshotting:** Implemented MD5 Hash snapshotting for transaction logs. This ensures transaction history remains consistent without generating duplicate data, paired with `X-Idempotency-Key` headers to protect against double-click checkouts.
- **Robust File Uploads:** Applied Magic Bytes validation (JPEG/PNG/WEBP) and an HTTP `MaxBytesReader` 2MB limit. Implemented automated disk cleanup when products are soft-deleted, resulting in zero disk bloat.
- **Randomized Jitter Cache:** Integrated the EMSifa API for Indonesian regional data. The cache TTL is randomized (1-3 hours) to prevent cache stampede problems when fetching external data.
- **Automated Testing:** Wrote 21 modular Unit and Integration Test scenarios using `testify`, achieving 100% successful execution across the suite.
